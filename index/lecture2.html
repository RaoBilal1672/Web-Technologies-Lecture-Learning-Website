Lecture 02: Tiered Web Architecture

Separation of Concerns

Tiered architecture separates presentation, application logic, and data into distinct layers, improving scalability and maintainability.

One-Tier Architecture

  • Presentation, logic, and data are tightly coupled in one environment.
  • Examples: Desktop calculator, local inventory tool.
  • Pros: Simple, low deployment complexity.
  • Limitation: Poor fit for large multi-user web systems.

Two-Tier Architecture

  • Client communicates directly with a server/data service.
  • Advantages: Simple mental model, easy for small systems, direct communication.

Three-Tier / N-Tier Architecture

  • Presentation Tier: Browser / UI
  • Application Tier: Business logic / API
  • Data Tier: Database / persistence

Each tier can evolve or scale with less impact on others.

Tiers vs. Layers

  • Tier: Physical/deployment separation (where components run).
  • Layer: Logical responsibility (how software responsibilities are organized).

Choosing an Architecture

Trade-offs include scalability, maintainability, and cost. Start simple when appropriate; separate concerns when complexity or scale justifies it.
